# Prose evidence policy

Status: owner-approved September 5, 2026; implemented and locally verified, coordinated release pending.

The owner approved making ambiguous keyword-only factual findings advisory while retaining blocking exact factual, capability, security and functional verification. The credit-restored Good Morning run proves the need: the scanner rejected insurer advice, a licensed-electrician reference and “not a guaranteed outcome”; repair deleted useful content. No new model, critic, orchestration or retry is authorized or introduced by this change.

## One boundary

The existing sensitive-prose pattern scanner supplies review topics, not determinations of semantic falsity. All of its unmatched body/metadata patterns become explicit `advisory.claim_evidence` / `advisory.metadata_claim_evidence` warnings. Keeping selected dictionary words blocking would preserve the same subject/negation problem and require a growing exception taxonomy. We do not change the shared scanner's source-ingestion classification or infer new business authority from an advisory.

The author must still write truthful, source-grounded copy, preserve genuine customer quotations and avoid unsupported promises. A warning says to examine source and sentence context, not delete a keyword. Supported exact bindings and source-context exceptions still suppress unnecessary warnings.

Blocking verification remains for invalid or mismatched SDK facts, the existing exact factual-marker checks in body and metadata (including supported numeric ratings), exact review destinations and other authorized links, form schema/destination/revision, source policy, runtime integrity, accessibility and functional failures. Managed authority, stored inputs, retained artifacts and owner source are not rewritten.

This is intentionally not a universal prose truth checker. An unsupported unbound credential, guarantee, availability sentence or customer quotation may receive only an advisory if its only signal was the sensitive-prose scanner. Those patterns never reliably validated all prose or all quotations before this change either. The policy does not license invention; source-faithful authoring, evidence-based experiment review and owner publication approval remain necessary. Do not describe a hard-gate pass as proof that every sentence is true.

## Verification and experiment

Fixtures must distinguish an advisory topic match from an exact mismatch. Preserve genuine unsupported prose as visible warnings, supported-context exemptions, altered/missing SDK fact rejection, wrong ratings/URLs, forms/security and functional rejection. Replay the retained first draft without editing its source and record both warning and error differences before spending another authoring run. Keep the failed run and costs; a successful replay is not a successful generation.

Deploy this verifier-only treatment with unchanged authoring model, guidance, runtime and cost fuse. Then run a fresh private ordinary-queue diagnostic. Judge completed source, actual pixels, copy, route purpose and repairs; do not claim stochastic superiority from one run. The fixed launch-acceptance screen and owner publishing/inbox journey remain separate requirements.
